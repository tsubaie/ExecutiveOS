# ExecutiveOS specification review

Date: 2026-09-07

The spec is **not ready for implementation as a binding contract**. Several accepted decisions require incompatible implementations, particularly around relationship ownership, job execution, private data, and document retention.

This review covers AGENTS.md, docs/README.md, documents 01–11, all nine feature specs, all seven ADRs, and the templates, read in the requested order. It is a specification review; predecessor behavior was not treated as authoritative. References below link to repository documents and name the relevant section. External references support framework and provider claims checked during the review.

Findings use **Blocker** for decisions likely to cause implementation rework, **Major** for significant gaps, and **Minor** for polish.

## Blockers to resolve first

- **B1 — The deployment and backup design violates the hard runtime constraint.** [02, Deployment and exclusions](docs/02-architecture.md#deployment) requires `postgresql-client`, `pg_dump`, tar, and a restore command, then forbids CLI subprocesses. Startup also invokes `pnpm db:migrate`. This is not merely an inconvenient implementation detail: backups are the declared migration rollback strategy in [ADR 0002, Consequences](docs/adr/0002-postgres-drizzle.md#consequences). **Change:** distinguish development commands from production runtime dependencies. Under the owner's strict no-CLI requirement, run migrations through an imported library and define an in-app, versioned logical backup/restore format with a database snapshot, file manifest, checksums, and maintenance-mode restoration. The trade-off is substantial backup engineering and no `pg_dump` compatibility. Do not silently retain the contradictory backup promise.

- **B2 — Atomic job claims do not establish safe execution.** [02, Background jobs](docs/02-architecture.md#background-jobs) reclaims work after 15 minutes without heartbeat renewal, a lease generation, or conditional completion. A slow first attempt can continue after a second instance claims the same job; both can publish results. “Every handler is idempotent” does not make repeated Claude calls deterministic or prevent duplicate charges. [The jobs schema](docs/03-data-model.md#jobs) also cannot express Meetings' `(document, locale)` deduplication rule. **Change:** specify at-least-once execution, renewable leases, an attempt/fencing token, completion conditional on current ownership, and atomic result publication. Add an explicit deduplication key, immutable input/prompt versions, attempt records, cancellation, deadlines, and scheduler occurrence uniqueness. Test termination before and after every persistence boundary.

- **B3 — Structural relationships and the graph have competing write authorities.** [Links, Relations and Behaviors](docs/features/links.md#relations) calls structural fields the source of truth, but the generic API lets users add/remove their mirror relations. Its acceptance criterion says adding `discussed_in` creates an agenda appearance; [Meetings' invariants](docs/features/meetings.md#data-model) describe the opposite direction, agenda → graph. An agenda also permits two items referencing the same KPI, while the graph permits only one corresponding edge. Removing one agenda item could remove the other's relationship. **Change:** maintain a finite relationship registry specifying cardinality, authoritative storage, writable operations, projection, and deletion behavior. Prefer deriving structural edges through a shared SQL projection and storing only contextual edges. This adds query composition but removes synchronization writes. If mirrors remain, give them provenance and prohibit direct generic mutation.

- **B4 — Meetings introduces privacy without an authorization model capable of enforcing it.** [02, Authentication and authorization](docs/02-architecture.md#authentication-and-authorization) and [ADR 0005, Decision](docs/adr/0005-auth-model.md#decision) allow every member to read/write all module data. [Meetings, Overview](docs/features/meetings.md#meetings) makes `personal_notes` author-only, yet stores one field on the shared meeting. API guards alone do not protect direct service calls, audit diffs, job payloads, server rendering, or shared caches. **Change:** explicitly define private notes as separate `(meeting_id, user_id)` records—or remove the privacy claim. Require actor-aware service authorization and response projection on every access path, including audit/history and AI inputs. Specify whether administrators and backup operators can access this data.

- **B5 — File lifecycle requirements cannot be implemented against the specified schema.** [Meetings' schema and invariants](docs/features/meetings.md#data-model) require soft-deleting briefs, although briefs have no `deleted_at`. [Meeting Prep pipeline, Retention](docs/features/meetings.md#meeting-prep-pipeline-in-process) deletes old files while retaining briefs and extracted text, but `meeting_documents.file_id` is a restrictive FK; deleting the document instead cascades its briefs. **Change:** distinguish document metadata, immutable file metadata, binary availability, and derived analyses. Define `available/purged/missing` binary states, reference-aware garbage collection, deletion provenance, and restore rules. Specify the write protocol for file upload plus DB insert, including orphan cleanup and crashes. Backups must preserve one consistent database-and-file manifest, not two independently timed copies.

- **B6 — The mandatory architecture rules prohibit required feature code.** [02, Module anatomy](docs/02-architecture.md#module-anatomy-mandatory) allows an exact layout, then requires `jobs.ts`; [06, Layers](docs/06-ai-integration.md#layers) adds `ai.ts` and prompt directories. [07, Layering](docs/07-coding-guidelines.md#layering-rules-lint-no-restricted-imports) prevents repos importing `core/links`, although `linkedTo()` is mandatory. It prevents module UI importing other module UI, while [Committees' audit](docs/features/committees.md#audit-items) requires exported Tasks components. UI may import schemas only as types, although forms require their runtime Zod schemas. **Change:** settle one enforceable module manifest and import matrix before building the audits. Permit cohesive subdirectories, separate client-safe validation from Drizzle definitions, and explicitly define reusable cross-module UI exports.

## 1. Architecture — Needs change

A long-lived Next.js server with an in-process PostgreSQL queue is viable for this deployment model. Replacing it with another framework would not solve its missing lifecycle guarantees. PostgreSQL explicitly identifies queue consumers as a use case for `SKIP LOCKED`; the unsupported leap is from safe claiming to safe execution. [PostgreSQL documentation](https://www.postgresql.org/docs/16/sql-select.html).

- **Major — Specify process initialization and shutdown.** [02, layout and runner startup](docs/02-architecture.md#repository-layout) places instrumentation at repository root despite using `src/app`. Next documents placement inside `src` when that directory is used, and `register()` must finish before serving requests. **Change:** specify `src/instrumentation.ts`, initialize once, start—but do not await—the perpetual loop, disable execution during build/test unless explicitly enabled, and define SIGTERM drain/abort behavior. Include a test against the built standalone image. [Next.js documentation](https://nextjs.org/docs/app/api-reference/file-conventions/instrumentation).

- **Major — Multi-instance support is only partially designed.** [02, jobs and deployment](docs/02-architecture.md#background-jobs) does not define migration serialization, scheduler leadership, shared file visibility, or cluster-wide concurrency. Two instances with local volumes cannot reliably execute one another's file jobs. **Change:** support one application instance for v1, while retaining crash-safe queue semantics. If multiple instances remain supported, require shared storage, a migration lock, unique schedule occurrences, and cluster-wide admission limits. Add the missing `schedules` schema and missed-run policy.

- **Major — Resource limits apply to too little work.** [ADR 0007, Consequences](docs/adr/0007-files-and-native-pdf-input.md#consequences) specifies brief concurrency one; [02, Background jobs](docs/02-architecture.md#background-jobs) specifies only global concurrency two. Inline AI bypasses both. Uploads, DOCX expansion, hashing, encoding, and password hashing share application resources. Streaming the response does not bound the input buffer or JSON serialization. **Change:** define admission limits for uploads, extraction, and all AI calls; queue length and storage quotas; memory headroom; reserved capacity for interactive requests; and overload responses. Start with one expensive document job globally.

- **Major — The event bus is an unnecessary correctness boundary.** [02, Domain events](docs/02-architecture.md#domain-events) asserts synchronous events execute inside the originating transaction, without specifying transaction propagation or awaiting asynchronous subscribers. A normal Node EventEmitter ignores listener return values. **Change:** use explicit, awaited service orchestration for invariants, audit writes, and task creation; reserve events for nonessential notifications. Any durable reaction should be inserted into the jobs table in the originating transaction. This is easier to trace than implicit subscription side effects. [Node documentation](https://nodejs.org/api/events.html).

The simplest robust design remains one Next.js process, one bounded durable queue, explicit transactions, and local immutable files. Inline AI is optional complexity; queueing all model calls would simplify retries, admission, cancellation, and accounting at the cost of modest polling overhead.

## 2. Data model — Needs change

- **Major — The structural/contextual classification rule is conceptually wrong.** [03, Link table summary](docs/03-data-model.md#link-table-summary) bases integrity on whether a relationship appears and is filtered on a list. UI presentation should not determine relational ownership. Attendees are many-to-many but structural because they have roles and authoritative membership; minutes are constrained ownership despite not being a universal list field. **Change:** classify by domain cardinality, lifecycle, relationship attributes, and invariants. Enumerate every v1 relationship; require a decision for additions rather than asking agents to interpret the heuristic.

- **Major — “Everything about X” is not currently complete.** [ADR 0006, Decision](docs/adr/0006-hybrid-linking-model.md#decision) retains numerous structural FKs, but [Links' vocabulary](docs/features/links.md#relations) mirrors only some. A meeting's minutes, committee, documents, and their analyses are not uniformly represented. Notes list threads while graph links target individual notes. **Change:** define a context query as a union of authoritative structural edges and contextual edges, with explicit direct-versus-transitive scope, deduplication, relation filters, and thread aggregation. Do not promise arbitrary completeness through the current graph alone.

- **Major — People, task owners, and users duplicate identity without reconciliation rules.** [People, Data model](docs/features/people.md#data-model) allows multiple people to reference one owner/user; [task owners](docs/03-data-model.md#task_owners) independently reference users and require unique names, while People explicitly permits homonyms. Linking a person to an existing owner does not require backfilling old task mirrors. **Change:** use People as the task-owner identity, with an assignable/active flag and optional user association. If separate owners are retained, specify uniqueness, conflicting user mappings, rename propagation, backfill, and merge behavior.

- **Major — Soft-delete restoration needs provenance.** [Links, Behaviors](docs/features/links.md#behaviors) says restore links, without distinguishing links deleted manually before the entity, links whose other endpoint remains deleted, or replacement links. [Tasks' invariants](docs/features/tasks.md#data-model) use matching timestamps to identify cascade children, but other modules do not. **Change:** define a deletion operation ID or equivalent provenance, restore only that operation's descendants, and preserve independent deletions. Specify uniqueness conflicts during restore and the purge ordering for restrictive FKs.

- **Major — Denormalized initiative fields need concurrency and ordering rules.** [03, Initiatives](docs/03-data-model.md#initiatives) and [Initiatives' invariants](docs/features/initiatives.md#data-model) leave “latest” ambiguous under same-day updates, backdating, edits, deletes, and concurrent writes. Progress is called soft-deletable but lacks `deleted_at`. **Change:** define `(business_date, created_at, id)` ordering, serialize mutations on the parent, recompute after every relevant write, and decide whether these few scalar projections justify denormalization at v1 scale.

- **Major — Numeric transport can lose declared precision.** [03, Global conventions](docs/03-data-model.md#global-conventions) converts `NUMERIC(18,4)` into JavaScript numbers, which cannot exactly represent its full range at four decimal places. **Change:** either constrain the supported magnitude/precision and document rounding, or transport decimal strings with decimal-aware calculations. Adjust [04's “numbers are numbers” rule](docs/04-api-conventions.md#response-envelopes) accordingly.

- **Major — Search and indexes are aspirational rather than specified.** [04, Lists](docs/04-api-conventions.md#lists-filtering-sorting-paging) calls `ILIKE` “full-text search” and requires generated `search_text` columns absent from the schemas. Searching agenda titles or all notes in a thread crosses tables. Indexing each filtered column, as [03 requires](docs/03-data-model.md#global-conventions), does not define useful composite indexes or substring-search indexes. **Change:** name searchable fields, Arabic normalization behavior, wildcard escaping, search projections, and indexes matched to actual query plans. Bound thread details, graph expansion, history, and job/audit retention.

- **Major — Migration policy blocks required database features.** [03, Tasks](docs/03-data-model.md#tasks) requires a subtask trigger, but [Migration rules](docs/03-data-model.md#migration-rules) allow handwritten SQL only for backfills. “Every migration is idempotent” also confuses safe repeated migration execution with making every DDL statement replayable. **Change:** allow reviewed custom migrations for triggers, indexes, and unsupported constraints; require the migration runner to apply each migration once under a lock. Audit PostgreSQL catalogs for those objects, not only `information_schema`. Drizzle supports custom DDL migrations. [Drizzle documentation](https://orm.drizzle.team/docs/kit-custom-migrations).

UUID v7 itself is **Sound** here. Keep it, but specify the generator and do not treat UUID ordering as an exact business timestamp or as authorization. Standard-column requirements need an explicit table classification: several history, junction, settings, and editable child tables presently violate the universal rules in [03, Global conventions](docs/03-data-model.md#global-conventions).

## 3. AI integration — Needs change

The named Opus/Sonnet models and fallback beta are documented; they should not be flagged as invented. Their existence does not establish compatibility for every configurable model or fallback combination. [Model catalog](https://platform.claude.com/docs/en/models/overview), [fallback documentation](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback).

- **Major — The upload limit is wrong for base64 input.** [06, Document input](docs/06-ai-integration.md#document-input) and [ADR 0007, Decision](docs/adr/0007-files-and-native-pdf-input.md#decision) equate a 32 MB uploaded PDF with a 32 MB request. Base64 alone expands it to roughly 42.7 MB, before context and JSON overhead. The documented page limit also depends on context-window size, and dense PDFs can exhaust context earlier. **Change:** enforce encoded-request and context budgets separately from upload size; use a lower conservative binary limit plus preflight checks. [Claude PDF requirements](https://platform.claude.com/docs/en/build-with-claude/pdf-support).

- **Major — Native PDF is a reasonable default, but not a universal replacement for extraction.** [ADR 0007, Alternatives](docs/adr/0007-files-and-native-pdf-input.md#alternatives-considered) asserts text-only input loses page references; page-aware extraction can retain them. Native PDF is useful for charts and layout, with higher resource/token costs and imperfect visual interpretation. **Change:** keep native PDF for visual documents, allow a clearly labeled text path, and reject or request splitting when limits are exceeded. Do not silently truncate. Treat page references as model claims requiring range checks and source inspection, not verified citations.

- **Major — DOCX conversion is an unresolved promise.** [Meetings, Documents](docs/features/meetings.md#meetings) promises conversion; [pipeline](docs/features/meetings.md#meeting-prep-pipeline-in-process) says “when possible”; [roadmap](docs/11-roadmap.md#open-decisions) leaves the converter undecided. **Change:** ship DOCX as text-only with explicit layout limitations, or defer it. Mammoth converts to HTML/text and warns that its output is unsanitized; it does not establish faithful PDF conversion. Define ZIP expansion and parser resource limits. [Mammoth documentation](https://github.com/mwilliamson/mammoth.js/).

- **Major — Persist exact generation inputs and stale-result policy.** [06, Prompt construction and safety](docs/06-ai-integration.md#prompt-construction-and-safety) retains old prompts until jobs no longer reference them, but jobs do not explicitly store capability version. [Notes' refinement table](docs/03-data-model.md#note_refinements) lacks the original content revision used to generate a proposal. **Change:** snapshot prompt/model policy, locale, input entity versions, selected document hash, and learnings version. Applying to a changed note must conflict or present a deliberate merge; duplicate Apply requests must not create duplicate tasks.

- **Major — Structured output specifies shape, not factual correctness.** [Notes' AI rules](docs/features/notes.md#ai) promise preservation of all facts and no invented decisions. [Meetings' AI section](docs/features/meetings.md#ai) does not fully define `BriefSections`: generic `items`, verdict placement, bounds, and section-specific fields remain open. **Change:** provide complete discriminated schemas, source-linked evidence fields, truncation/refusal handling, and reviewed evaluation examples for unsupported claims, Arabic fidelity, owner attribution, and page references. Label factual preservation as an evaluation target, not a consequence of Zod validation.

- **Major — The learning loop is automatic preference mutation.** [Meetings, Feedback](docs/features/meetings.md#meeting-prep-pipeline-in-process) automatically makes distilled output the next prompt's guidance, conflicting with [01's explicit-application principle](docs/01-vision-and-scope.md#product-principles). One member's feedback becomes global “Executive preferences”; simultaneous distillations can lose feedback, and a queued job can undo an admin reset. **Change:** produce a reviewable learning proposal with source provenance, scope, base version, and explicit activation. Serialize or compare-and-swap versions; make reset invalidate earlier pending proposals. Prefer committee/document-category scope for domain notes. Test contradictory feedback, concurrent submissions, reset during generation, and poisoning attempts.

- **Major — No tools does not eliminate indirect prompt-injection effects.** [06, Safety](docs/06-ai-integration.md#prompt-construction-and-safety) limits direct model actions, but malicious content can still alter recommendations, owner suggestions, learning proposals, or generated links/images. **Change:** keep learning content untrusted, prevent fetched remote resources in rendered AI markdown, restrict URL schemes, distinguish evidence from recommendations, and test adversarial documents. Schema validity must not imply trustworthy advice.

- **Major — Cost controls omit the expensive paths and concurrent admission.** [06, Cost controls](docs/06-ai-integration.md#cost-controls) rate-limits breakdown and tag suggestions, but not briefs, regeneration, translation, or distillation. The token cap lacks reservation, month/timezone semantics, and queued-job handling. [Invocation storage](docs/03-data-model.md#ai_invocations) omits cache-write usage and the version field required elsewhere. **Change:** account per attempt, reserve estimated usage before admission, limit all capabilities, distinguish soft warnings from enforced limits, record effective model and complete usage, and show estimated monetary cost with versioned pricing. Coordinate SDK retries with queue retries and the inline 60-second deadline.

- **Major — BYOK setup needs an operational contract.** [06, Model policy](docs/06-ai-integration.md#model-policy) hardcodes an allowlist and mandatory features without capability negotiation. **Change:** add a connection/access check, supported-model feature matrix, actionable invalid-key/billing/rate-limit errors, key-rotation instructions, and explicit data-submission disclosure. The current [“only explicitly submitted PII” claim](docs/06-ai-integration.md#prompt-construction-and-safety) must cover automatically included owner directories, attendees, agenda context, and previous feedback.

- **Minor — Cache hits cannot be a universal pass condition.** [06, Testing AI](docs/06-ai-integration.md#testing-ai) requires second-call hits for every capability, although cache eligibility has minimum prompt lengths. **Change:** assert hits only for eligible fixtures and test correct cache configuration separately; do not pad prompts merely to pass the audit. [Prompt caching documentation](https://platform.claude.com/docs/en/build-with-claude/prompt-caching).

## 4. API and UI conventions — Needs change

- **Major — Response contracts conflict and are incomplete.** [04, Envelopes](docs/04-api-conventions.md#response-envelopes) forbids omitted fields, while totals and job fields are optional; health returns a bare object; file and SSE routes have no declared exceptions. AI introduces error codes absent from the central table. OpenAPI registration shows only input schemas. **Change:** declare request and response schemas, status codes, nullable-versus-optional rules, and explicit binary/SSE/204 exceptions for every endpoint. Specify nested validation error paths, localized messages, retryability, and stable machine-readable reasons.

- **Major — Cursor pagination is underspecified for the actual sorts.** [04, Paging](docs/04-api-conventions.md#lists-filtering-sorting-paging) says “sort key + id”; [Tasks' default](docs/features/tasks.md#behaviors) uses four ordering components, including date-relative bands and enum priority. **Change:** specify every ordered tuple, semantic enum rank, null placement, collation, cursor version, and filter/sort binding. Decide what happens across midnight or concurrent sort-key edits. Define whether rail counts incorporate facets/search and whether grouping counts cover loaded rows or the full result.

- **Major — Optional timestamp concurrency is insufficient for multi-user editing.** [04, Concurrency](docs/04-api-conventions.md#concurrency) permits two mechanisms with no precedence, different precision, and no required atomic update predicate. Action routes and child writes have no equivalent. **Change:** use a required integer revision for editable records, atomically compare-and-increment it, and specify aggregate revision rules. Autosave should serialize or coalesce edits and preserve the local draft on conflict. Add idempotency keys for create/apply operations, especially where [05](docs/05-ui-guidelines.md#data-fetching-and-mutations) promises a Retry button after every mutation failure.

- **Major — CSRF is defensible but conditional.** [04, CSRF](docs/04-api-conventions.md#auth-endpoints) is not wrong merely because the header value is public: a cross-origin simple form cannot supply it. Its effectiveness depends on CORS and complete enforcement. **Change:** specify same-origin deployment, deny credentialed cross-origin access, validate Origin against configured `APP_URL`, and test login/setup, multipart upload, and all mutations. Define trusted-proxy handling. A custom header is an established approach under these conditions. [OWASP guidance](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).

- **Major — The entity framework cannot yet implement its advertised API.** [Entity pages, Public API](docs/features/entity-pages.md#public-api) exposes `save/delete/restore` without accepting mutation adapters or typed patch/create contracts. It has single selection while Notes requires multiselect merge. **Change:** define these interfaces, loading/disabled states, create completion, selection cardinality, filter serialization, and next/previous behavior across pages. Build it alongside Tasks and Notes; do not freeze a universal framework before both work.

- **Major — Cache invalidation omits cross-module and cross-user changes.** [Tasks' query keys](docs/features/tasks.md#api), [Links' invalidation](docs/features/links.md#api), and [Meetings' polling](docs/features/meetings.md#api) omit affected list statistics elsewhere. Meeting prep status is locale-dependent, but list/detail keys omit locale. **Change:** define a mutation dependency map, previous-and-new endpoint invalidation, locale/user cache scoping, logout clearing, and bounded refresh for other members' edits. Real-time collaboration can remain excluded.

- **Major — RTL and accessibility claims need observable behavior beyond classes.** [05, Accessibility](docs/05-ui-guidelines.md#accessibility) assumes primitives guarantee correct composition. [05, i18n](docs/05-ui-guidelines.md#internationalization-and-rtl) leaves user timezone precedence and calendar convention unresolved. **Change:** specify mixed-direction isolation, date-only parsing, Gregorian/Hijri policy, numeral options, accessible chart tables, and keyboard/focus behavior in nested editors. Measure rendered overflow and usable focus at narrow widths; `dir="rtl"` and axe alone cannot prove full RTL usability.

## 5. Guidelines, tests, and audits — Needs change

- **Major — Several “mechanical” rules are judgments.** [07, File and function limits](docs/07-coding-guidelines.md#file-and-function-limits) requires splitting “by responsibility”; [07, docs audit](docs/07-coding-guidelines.md#comments-and-docs) refers to the “last significant change”; [09, Agent self-audit](docs/09-audit-checklists.md#g-agent-self-audit-before-every-hand-off) asks whether code was copied. **Change:** label each rule as static, runtime, or human-reviewed. Add dependency-cycle checks, duplication detection, and requirement IDs mapped to tests. A date stamp is not evidence of spec parity.

- **Major — Test counts encourage fake tests.** [09, Automated audits](docs/09-audit-checklists.md#a-automated-audits-pnpm-auditall) requires seven test files with three `it()` blocks each; [08](docs/08-testing-strategy.md#required-tests-per-module) lists layers, not seven universal files, and AI tests are conditional. **Change:** remove syntax counts. Require named scenarios per invariant and selected mutation tests for critical rules. Test audit scripts themselves against deliberately violating fixtures; exempt those static-tool tests from the ban on reading source fixtures.

- **Major — The strongest failure modes lack dedicated test contracts.** [08, Required tests](docs/08-testing-strategy.md#required-tests-per-module) covers ordinary behavior but does not explicitly require competing DB transactions, job crash recovery, duplicate apply requests, privacy across alternate read paths, or backup consistency under mutation. **Change:** add core suites for these cases. Use independent DB connections for races, process termination for runner recovery, and restore checks over files and relationships. Factory-created valid data alone cannot prove database constraints reject invalid writes.

- **Major — Layering checks need to follow re-exports and client boundaries.** [07's import restrictions](docs/07-coding-guidelines.md#layering-rules-lint-no-restricted-imports) can be undermined by barrels that re-export forbidden modules. **Change:** validate the dependency graph, mark server-only modules, inspect client bundles, and test fixture imports through aliases, re-exports, and dynamic imports. Otherwise an agent can accidentally pull DB or secret-bearing code into client paths while satisfying direct-import patterns.

- **Major — Portability and i18n greps overclaim coverage.** [09, Automated audits](docs/09-audit-checklists.md#a-automated-audits-pnpm-auditall) cannot identify every real name or resolve dynamic translation keys. A timezone ban also conflicts with [Tasks' required timezone tests](docs/features/tasks.md#required-tests). **Change:** use explicit allowed locations for configuration and fixtures, scan secrets separately, type translation namespaces, validate ICU arguments/plurals, and add tests with different organizations and defaults. Keep denylist checks as tripwires, not guarantees.

- **Major — Governance instructions contradict each other.** [AGENTS.md, Non-negotiable rules](AGENTS.md#non-negotiable-rules) requires updating ADRs; [ADR policy](docs/adr/README.md) forbids editing accepted ADRs. [10, Implementer procedure](docs/10-agent-workflow.md#implementer-procedure) permits conservative assumptions while its later rules prohibit guessing. **Change:** define precedence and a single superseding-ADR policy. Distinguish authorized implementation work from a newly discovered decision requiring escalation.

- **Minor — Some strictness adds ceremony rather than protection.** [07, compiler and size rules](docs/07-coding-guidelines.md#language-and-compiler) bans all casts outside repos, constrains every unknown to Zod, and counts props/state hooks. These can push agents toward unsafe repo casts, giant reducer objects, or arbitrary splitting. **Change:** keep strict types and complexity limits, allow narrowly documented boundary assertions and native error narrowing, and apply adjusted rules to generated primitives and tests. Define the measurement environment for [09's 300 ms and 250 KB budgets](docs/09-audit-checklists.md).

The required-test lists are **not sufficient by themselves**. They are inventories; the missing protection is adversarial scenario coverage and independent verification that those scenarios fail when the relevant behavior is broken.

## 6. The nine feature specs — individual findings

These supplement the shared blockers above. Blanket requirements such as “all invariants” do not resolve missing behavior or demonstrate that a particular case is covered.

### Entity pages — Needs change

- **Major:** [Behaviors](docs/features/entity-pages.md#behaviors) does not resolve simultaneous `id` and `new`, deep links outside the current filter, deletion of the selected row, or navigation with unsaved/failed edits. A 404 both displays an inline state and removes the selection that owns it. Specify the state machine and precedence.
- **Major:** [Required tests](docs/features/entity-pages.md#required-tests) omit overlapping autosaves, infinite-page navigation, account switching, and framework multiselect. Add those scenarios. “Share zero page-level code” in [acceptance](docs/features/entity-pages.md#acceptance-criteria) is an internal architecture check, not an externally observable criterion.

### Tasks — Needs change

- **Major:** [Behaviors](docs/features/tasks.md#behaviors) allow status through general update schemas while completion has special side effects. Grouping top-level tasks does not say what happens when one already has children. Breakdown excludes tasks with children but does not exclude a task that is itself a subtask. Define the allowed transition and reparenting matrix.
- **Major:** [Ordering invariant](docs/features/tasks.md#data-model) lacks the DB constraint and collision-safe reorder strategy. Define whether subtasks appear in global lists/counts and whether “week” means the documented rolling seven days.
- **Major:** [Tests and acceptance](docs/features/tasks.md#acceptance-criteria) need explicit cases for midnight refresh of an already-open UI, competing complete/add-subtask operations, duplicate breakdown application, and restoring only cascade-deleted children. “Without a deploy” is too weak; state a refresh deadline.

### Notes — Needs change

- **Major:** [Merge and archive behavior](docs/features/notes.md#data-model) does not define reverse-merge storage/API, handling of later edits, deleted notes, or a source that contains meeting minutes. Filters can match different notes within one thread; specify whether all facets must match the same note.
- **Major:** [Refine endpoint](docs/features/notes.md#api) returns 409 for pending refinement, while [acceptance 6](docs/features/notes.md#acceptance-criteria) returns the existing job. Distinguish an active job from a completed proposal awaiting review. Define tag-overflow handling, repeated task indexes, discarded-proposal identity, and stale-note application.
- **Major:** [Required service tests](docs/features/notes.md#required-tests) explicitly cover invariants 1–7, omitting the added minutes invariant 8. Add concurrent minutes creation, merge/move of minutes, and `agreed_in` creation on refinement. Fixture rendering does not establish the factual-preservation promise.

### Committees — Needs change

- **Major:** [Detail behavior](docs/features/committees.md#behaviors) promises Activity without an endpoint, authorization rules, or a definition of “linked items” over historical changes. It omits a Meetings tab despite the module's stated meeting-history purpose. Define the history query and meeting navigation.
- **Major:** [Query invalidation](docs/features/committees.md#api) refreshes detail but not card statistics. Specify list invalidation and handling of both old/new committees after reassignment.
- **Major:** [Tests](docs/features/committees.md#required-tests) should name mixed-thread counting, deleted versus archived links, activity visibility, and reassignment invalidation. Define the field-error mapping for duplicate-name 409 responses; the general API does not currently guarantee it.

### KPIs — Needs change

- **Major:** [Effective-target policy](docs/features/kpis.md#behaviors) compares the latest reading, however old or future-dated, with a current or future target. Missing readings become `no_target`, conflating missing measurement with missing target. Positive-only targets exclude legitimate zero-defect and negative-value measures. These are product assumptions stated as universal rules. Define supported KPI classes, reading freshness, applicable periods, and separate missing-data statuses.
- **Major:** [Objective deletion](docs/features/kpis.md#behaviors) clears relationships immediately, contradicting the broader retain-until-purge approach. The lower-is-better gauge also needs a meaning distinct from raw `current/target` “achievement.”
- **Major:** [Required tests](docs/features/kpis.md#required-tests) need future/stale readings, threshold-setting invalidation, target deletion, quarter rollover in an open UI, and a defined lower-direction gauge. “RTL charts” needs explicit time-axis and reading-order behavior.

### Initiatives — Needs change

- **Major:** [Invariants and behaviors](docs/features/initiatives.md#data-model) conflict over adding backdated updates: “sets health” versus “latest update determines health.” Reopen has an endpoint but no resulting status. Closing freezes updates yet creates a final update. Define operation ordering and transition behavior.
- **Major:** The persisted `late` status creates a second clock-dependent truth: extending a due date or reopening a deliverable has no normalization rule. [Acceptance](docs/features/initiatives.md#acceptance-criteria) mentions a late filter absent from the documented API. Prefer computed lateness for v1.
- **Major:** [Tests](docs/features/initiatives.md#required-tests) need backdated/concurrent update ordering, edit of the latest update, due-date extension, reopen, and competing progress upserts. Give “after the daily job” a concrete schedule and catch-up policy if the job remains.

### Meetings — Needs change; contains multiple blockers

- **Major:** [Brief output](docs/features/meetings.md#meeting-prep-pipeline-in-process) creates proposed tasks with `discussed_in`, whereas Actions is defined as `agreed_in`; [acceptance 4](docs/features/meetings.md#acceptance-criteria) expects those proposals in Actions. The proposed `source` relation to a document is illegal under Links' task↔note-only vocabulary. Define proposed versus agreed actions explicitly, plus a source reference that can identify the exact brief version and item.
- **Major:** [Brief schema](docs/features/meetings.md#data-model) requires `sections` before a `generating` record has output. Version allocation has no concurrent-write rule. [Request syntax](docs/features/meetings.md#api) is invalid, and translations have no source-brief reference. Define a valid discriminated request and state schema; distinguish analysis from translation provenance.
- **Major:** [Prep status](docs/features/meetings.md#data-model) has no failed/stale state and can report ready while a regeneration is running or context has changed. Define precedence, active document selection, freshness, and locale-specific counting.
- **Major:** [Feedback uniqueness](docs/features/meetings.md#data-model) allows only one feedback per brief across all users. Decide whether feedback is per user or an office-approved assessment, who can amend it, and whether edits trigger re-distillation.
- **Major:** [Duplicate meeting](docs/features/meetings.md#meetings) excludes “time-bound items” without defining them. Next-hour defaults, cancelled/upcoming overlap, minutes uniqueness, missing/purged documents, and extraction-before-generation behavior also need exact rules.
- **Major:** [Required tests](docs/features/meetings.md#required-tests) need explicit cross-user privacy, simultaneous en/ar generation, regenerate/translate races, repeated action creation, upload/DB crash cleanup, parser exhaustion, binary retention with surviving briefs, and feedback/reset races. Acceptance 5 proves that learning text is included, not that the next brief improves. Replace the improvement claim with a measured evaluation target.

### People — Needs change

- **Major:** [Merge behavior](docs/features/people.md#behaviors) cannot simply “move” two different owner IDs or user IDs into one target. It also omits `meeting_attendees`, so the graph can move while the authoritative roster remains attached to the source. Define conflict resolution and structural rewrites; defer reversible merge if its history model is not specified.
- **Major:** [Create behavior](docs/features/people.md#behaviors) promises creating owners despite unique owner names and permitted person homonyms. Define which users may create/activate owners, and a warning response that does not accidentally create duplicates.
- **Major:** [Required tests](docs/features/people.md#required-tests) need conflicting merges, owner backfill, attendee deduplication, deletion/restoration, and stats invalidation. “Leaves one person” should specify visible directory entries and preserved history, since the source remains soft-deleted.

### Links — Wrong as a writable mirror model; Needs change overall

- **Major:** [Canonical ordering](docs/features/links.md#data-model) is safe only when semantic roles remain recoverable. Define inverse labels, allowed endpoint pairs, self-links, and duplicate handling; do not let alphabetical storage order imply semantic direction.
- **Major:** [Every-list filtering](docs/features/links.md#behaviors) conflicts with API tables omitting `linkedTo/relation`, particularly Notes' thread aggregation. Define the filter contract per returned entity type.
- **Major:** [Required tests](docs/features/links.md#required-tests) need duplicate joins across relations, concurrent endpoint deletion/insertion, restoring with a deleted opposite endpoint, manually removed versus cascade-removed edges, and repeated agenda references. The claim that adding a graph edge populates an agenda is observable but contradicts the authoritative-write design; it cannot remain a passing criterion unchanged.

## 7. Scope and product — Needs change

- **Major — v1 contains too many independent products.** [01, Scope](docs/01-vision-and-scope.md#v1-scope) combines task management, threaded knowledge, a strategy scorecard, portfolio tracking, document analysis, persistent learning, a context graph, and deployment administration. [11, Roadmap](docs/11-roadmap.md) additionally front-loads a universal UI framework and custom audit infrastructure. **Change:** release a complete office workflow—meeting → documents → reviewed brief → minutes → owned actions—with People, Committees, Notes, Tasks, and Links supporting it.

- **If forced to cut two modules: cut KPIs and Initiatives.** Their [scorecard](docs/features/kpis.md#behaviors) and [portfolio behaviors](docs/features/initiatives.md#behaviors) introduce a separate strategy-management domain: measurement policy, quarterly targets, historical calculations, chart semantics, deliverables, and denormalized progress. They are less necessary to the meeting-to-action workflow than the remaining modules. The trade-off is losing the strategic-review scorecard; retain free-text agenda items and add typed strategic links when those modules arrive.

- **Major — The promised executive entry point is missing.** [01, Purpose](docs/01-vision-and-scope.md#what-executiveos-is) promises one screen answering decision and attention questions, while [exclusions](docs/01-vision-and-scope.md#explicitly-out-of-v1) remove My Day. [05's navigation](docs/05-ui-guidelines.md#layout-shell) still includes an undefined Home slot. **Change:** specify a small landing page linking upcoming meetings, preparation failures, overdue actions, and pending AI reviews. It need not become a new insights product.

- **Major — The executive's identity is absent.** [01's installation model](docs/01-vision-and-scope.md#who-it-is-for) is one executive office, yet no setting identifies the principal person. [Meeting briefs](docs/features/meetings.md#meeting-prep-pipeline-in-process) are generated from the initiating user's context and global preferences. **Change:** identify the executive principal separately from the logged-in operator, define office versus personal preferences, and specify how an assistant prepares material on that person's behalf.

## 8. Open-source readiness — Needs change

- **Major — Setup is not executable as described.** [README quick start](README.md#quick-start-target-once-implemented) copies an env file and starts Compose, while [configuration](docs/02-architecture.md#configuration) requires secrets and [security audit](docs/09-audit-checklists.md#d-security-audit-each-release-and-whenever-auth-settings-jobs-or-ai-change) forbids default database credentials. Production secure cookies also need a documented HTTPS path. **Change:** specify image selection, architecture support, credential initialization, TLS/reverse-proxy examples, volume permissions, minimum resources, and the exact supported local-development exception.

- **Major — Account recovery and bootstrap security are unfinished.** [ADR 0005](docs/adr/0005-auth-model.md#decision) has first-admin setup and admin-mediated reset, but no first-run claim protection, simultaneous setup serialization, last-admin protection, or recovery when the only admin loses access. “~400 lines” is an unsupported estimate. **Change:** define those operations and their tests, active-session invalidation on deactivation, absolute versus sliding expiry, bounded password-hash concurrency, and proxy-aware rate limiting. Provide a recovery mechanism consistent with no CLI.

- **Major — Several required product surfaces have no specifications.** [11, Skeleton](docs/11-roadmap.md#phase-1--skeleton) includes Users, Settings, backups, audit browsing, and jobs, while [09](docs/09-audit-checklists.md#a-automated-audits-pnpm-auditall) requires a feature spec per module. Comments are already embedded in feature specs but still an open scope decision. **Change:** add bounded contracts for these surfaces or remove their promises. Include settings defaults, per-role read/write allowlists, per-user preferences, and reset behavior.

- **Major — Upgrade and restore need a support policy.** [09, Release audit](docs/09-audit-checklists.md#f-release-audit) checks an upgrade but does not define supported source versions, downtime, failed-migration recovery, image/database compatibility, or file integrity after restoration. **Change:** document supported upgrade hops, migration locking and preflight, backup validation, restore drills including files, and interrupted-upgrade behavior. Restoring a backup also loses later writes; that trade-off must be explicit.

- **Major — Backups are not portable user export.** [01, Backups](docs/01-vision-and-scope.md#v1-scope) has no independent export commitment. **Change:** provide an admin export containing structured records, relationship IDs, Markdown notes/briefs, and original documents with a manifest. Define whether private notes, audit history, deleted data, and AI payloads are included. Add retention policies for derived sensitive text, not only source binaries.

- **Major — Security documentation is narrower than the attack surface.** [09, Security audit](docs/09-audit-checklists.md#d-security-audit-each-release-and-whenever-auth-settings-jobs-or-ai-change) emphasizes backup paths but Meetings adds arbitrary document parsing and file serving; [05](docs/05-ui-guidelines.md#mobile) adds a service worker. **Change:** specify upload signature checks, parser limits, download headers, external-resource policy, CSP, sensitive-cache exclusion, log/error redaction, and audit-diff exclusions. Add a vulnerability-reporting process and supported-version policy.

- **Major — License selection is delayed past architectural acceptance.** [README](README.md#license) and [11, Open decisions](docs/11-roadmap.md#open-decisions) leave it open. **Change:** select and include the license before soliciting implementation contributions, record dependency/font/asset notices, and establish contribution provenance. Any predecessor code reuse needs a separate rights decision; private availability is not authorization to redistribute it.

- **Minor — Remove signs of incomplete integration.** [01, Success criteria](docs/01-vision-and-scope.md#success-criteria-for-v1) still says “five modules”; [work-item template](docs/templates/work-item.md) omits Meetings and People; all specs have “Last verified” dates despite [the feature template](docs/templates/feature-spec.md) defining that as verification against code. **Change:** distinguish “spec reviewed” from “implementation verified,” update module inventories, and close or explicitly defer outstanding editor/converter/comment decisions.

## Three changes before any code is written

1. **Replace the relationship heuristic with an authoritative relationship and lifecycle contract:** ownership, cardinality, graph projections, private fields, deletion/restoration, files, and merges.
2. **Finish the production execution contract:** one-process startup, renewable/fenced jobs, deduplication, resource limits, immutable AI inputs, and a backup/restore design that actually obeys no CLI.
3. **Reduce v1 and make its contracts internally consistent:** defer KPIs and Initiatives, complete the meeting-to-action workflow, settle API/framework interfaces, and replace audit-by-file-count with named adversarial acceptance scenarios.

This spec is not ready to hand to implementing agents under its own “never guess” rule. Faithful agents will repeatedly stop on contradictions; permissive agents will invent incompatible interpretations and encode them into plausible tests. Resolve the blockers, publish one source of truth for each cross-module contract, and then assign small vertical slices whose acceptance scenarios include concurrency, recovery, authorization, and Arabic behavior.
