# Hand-off: fix/ui-mobile-chrome — the phone list gets its rows back

Status: complete for the three layout defects; **blocked** on one product decision (the bottom
bar) and one pre-existing repository failure (`pnpm build`). Both are recorded below.

## Summary

A 390 px phone gives an entity list 732 px between the shell header and the bottom bar. Tasks was
spending 377 px of that on its bar and statistics block before the first record, and KPIs was
drawing three of its fifty-two rows. Two of the three defects were outright bugs rather than
density: on KPIs the toolbar's settings group was `shrink-0` and measured 509 px inside a 390 px
screen, so Filter and Clear rendered past the end of the screen where nothing could reach them;
and on Home a grid item's automatic minimum let one committee named after a UUID stretch its
column past the track, carrying every section's "View all" off the edge. The third is EP-B40: the
featured readings are a scrolling line on a phone instead of a two-column block whose fifth tile
sat alone beside a hole. Everything was measured in a real browser before and after; nothing here
was judged by eye.

Each was confirmed to fail with the implementation reverted and pass with it restored. That check
caught two defects in the work itself: the first HOME-B13 test was vacuous, because its "ignore
boxes clipped by an ancestor" filter reached the shell root, which is `overflow-hidden`, and so
excluded every element on the page; and the EP-B40 change silently broke EP-B35, because
`@lg:grid` is a variant and out-ordered the `xl:hidden` that keeps the strip away from a rail
already showing the same readings. Both are fixed; the second is why the strip's `display` now
stays on the base layer.

## Blocked: `pnpm build` fails on `main`

`main` at d5ae97b does not build. Reproduced in a worktree created fresh, with `.next` deleted:
`/` and `/_global-error` fail to prerender with React internals reading from null
(`'use'`, `'useContext'`, and `'length'` of undefined across runs), an ignore-listed stack and a
changing digest. Eliminated by bisect, each with a cleared cache: the root page (a trivial page
still fails), the root layout (bare `html`/`body` still fails), `src/instrumentation.ts`
(no-op `register()` still fails), the `next-intl` plugin, `output: 'standalone'`, duplicate React
(one copy of 19.2.8), and the peer range (next 16.3.4 accepts `^19.0.0`).

`/` is the only statically prerenderable route in the application, so the accurate statement is
that this setup cannot statically prerender at all and `/` is where it shows. Consequently
`audit:browser`, `audit:bundle`, `audit:openapi`, `audit:a11y` and `audit:perf` have been dark,
and `pnpm audit:all` cannot have passed on `main` for some time. The next step is a minimal repro
or a Next version change; a dependency change is an escalation under `10-agent-workflow.md`, so it
is left as its own work item rather than taken here.

Note also that `pnpm test` truncates `users` but not `workspace`, so after a unit run
`scripts/db/e2e-account.ts` reports "existing" and every browser scenario fails at login. That
makes `audit:all`'s chaining of `audit:data` into `audit:browser` unrunnable locally without a
`pnpm db:reset` in between.

## Open questions

1. **The bottom bar carries seven items where five fit.** `docs/05 § Layout shell` shows
   `Home · Tasks · Meetings · Notes · Menu`, and names a module that does not exist; `ADMIN-B19`
   says administration "keeps its place in the mobile bar". A feature spec beats a guideline, so
   these conflict and the resolution is a product decision. Measured at 320 px: seven 44 px slots
   at 0 px gaps with labels of 36/36/36/43/73/26/84 px, so "People" and "Committees" render as one
   word at every width tested and "Administration" runs off the end. Options: (a) four
   destinations plus a Menu sheet, amending ADMIN-B19 in the same PR; (b) keep seven and scroll
   the bar, which satisfies ADMIN-B19 but hides destinations; (c) icons only below `lg`, which
   fits but costs the labels `05 § Density` protects for a 40+ audience. Recommendation: (a).
